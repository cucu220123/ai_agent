# 系统架构与端到端时序

```text
┌──────────────┐   ┌──────────────┐   ┌────────────────┐
│ CLI / FastAPI│──▶│ ParserAgent  │──▶│ RetrieverAgent │
└──────────────┘   └──────────────┘   └───────┬────────┘
                                               │ SQLite + GraphML
                                               ▼
                                       ┌────────────────┐
                                       │  PlannerAgent  │
                                       └───────┬────────┘
                                               ▼
                                       ┌────────────────┐
                                       │ GeneratorAgent │
                                       └───────┬────────┘
                                               ▼
                                       ┌────────────────┐
                                       │ ValidationRunner│
                                       └───────┬────────┘
                                    fail     │      pass
                              ┌──────────────┘        │
                              ▼                       ▼
                       ┌────────────┐         ┌───────────────┐
                       │ RepairAgent│────────▶│ CuratorAgent  │
                       └────────────┘  retry  └───────┬───────┘
                                                       ▼
                                             ┌─────────────────┐
                                             │ ReportGenerator │
                                             └─────────────────┘
```

工作流采用“确定性代码模板 + 可插拔 LLM 解释”的混合策略。LLM 负责理解、规划建议和解释；最终算法代码受统一接口和 AST 安全检查约束，避免模型输出不稳定导致系统不可复现。候选算法逐一验证，先筛选满足业务阈值的方案，再按主指标和运行时间排序。
