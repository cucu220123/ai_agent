# 系统架构与端到端时序

```text
┌──────────────┐   ┌──────────────┐   ┌────────────────┐
│ CLI / FastAPI│──▶│ ParserAgent  │──▶│ RetrieverAgent │
└──────────────┘   └──────────────┘   └───────┬────────┘
                                               │ SQLite + GraphML
                                               ▼
                                       ┌────────────────┐
                                       │  PlannerAgent  │
                                       └───────┬────────┘
                                               ▼
                                       ┌────────────────┐
                                       │ GeneratorAgent │
                                       └───────┬────────┘
                                               ▼
                                       ┌────────────────┐
                                       │ ValidationRunner│
                                       └───────┬────────┘
                                    fail     │      pass
                              ┌──────────────┘        │
                              ▼                       ▼
                       ┌────────────┐         ┌───────────────┐
                       │ RepairAgent│────────▶│ CuratorAgent  │
                       └────────────┘  retry  └───────┬───────┘
                                                       ▼
                                             ┌─────────────────┐
                                             │ ReportGenerator │
                                             └─────────────────┘
```

工作流采用“确定性代码模板 + 可插拔 LLM 解释”的混合策略。LLM 负责结构化建议、规划解释和风险提示；最终算法代码受统一接口和 AST 安全检查约束，避免模型输出不稳定导致系统不可复现。候选算法逐一验证，先筛选满足业务阈值的方案，再按主指标和运行时间排序。

增强版增加 `PluginRegistry`：任务类型、算法模板、资源画像和默认参数均可以注册；`AdvisorAgent` 使用 JSON 合约产生可审计建议，建议必须经过白名单过滤，不能直接注入任意代码或导入。验证执行采用独立进程和硬超时，失败结果会带着 stdout/stderr 回到 RepairAgent。
